# Implementation packages and prerequisites

This ordering is derived from the feature dependencies and known uncertainty, not folder age. It is an implementation proposal after the completed preparation; no mod files have been edited. See [matrix](feature-matrix.md) for every package gate.

## Package A Evidence and engine contracts

The user performs [debug run](debug-run.md). Reconcile executed build with source hashes, inspect current command/UI exports and complete the named native audits. Produce a contract note for query initialization, payment/hook consumption, war membership/removal, event/lists lifetime, GUI precedence and player succession.

Do not wait idle on one missing signature: review independent declarative differences. But do not implement a blocked behavior from an assumed signature. Where exports are insufficient, provide the smallest concrete user test and its expected observation.

## Package B Remove embedded knights and retain balance

Apply CD-KNIGHTS as one reviewed removal of 12 files, preserve other CustomDefines content and verify no remaining references. Retain the 23 verified define values; do not enable dormant innovation changes. Complete the standalone CustomDefines cold-start and native-knight regression before combining it with other mods.

CD-RULES/CD-LOBBY/CD-TOOLTIPS can follow only after UI gates. Rebase current relevant native types, preserving all newer branches; avoid carrying old entire-window/type structures forward. The post-start designer action must be supported by the engine, not just enabled by a button.

## Package C Shared conversion contract

Resolve MC-DISPATCH and SA-CONVERSION together. Define one audited actor/recipient/candidate contract for visibility, counts and execution; preserve normal consent and current native consequences. Implement standalone first, port its verified categories/schema/protection policy to bundle, then update the corresponding alerts without expanding their candidate sets.

Test standalone and bundle independently. Keep notification override experiments inactive. Block package certification until refusal/concession, cooldown, faith/rite and MP tests pass.

## Package D Simple transactions and resource corrections

After payment and hook contracts close, update SI-MONEY and SI-PARDON with their original amount/recipient/opinion policies and execution guards. Apply the source-confirmed resource unavailable threshold correction and modern decision pictures, verify text and council/loan/injury behavior. Test numerical deltas rather than presence of the menu.

If a current strong-hook use is not a pardon/removal, record that concrete conflict and ask for the intended policy before changing it. If loan localization totals differ from rounded existing modifiers, retain balance values and document/correct descriptive text after verifying intended totals; do not rebalance loans without a behavior decision.

## Package E War selection and notifications

Resolve LW membership/removal/lifetime gates and SA-JOIN/SA-STOP query gates. Implement one verified withdrawal path for the existing ten-slot selector and propagate to both identical distributions. Preserve all six rule settings and exact consequences. Then update affected war start/join notifications after baseline comparison establishes whether custom delivery duplicates native messages.

Validate stale-war targets before charging. Test the highest current title tier and two-player independent selection. Notification deduplication must preserve intended attacker/defender reasons rather than collapsing every message into one.

## Package F Delayed education and religious authority

Finish SI-EDUCATION lifecycle audit, then preserve payer/student separation and exactly-once student completion. Finish SI-EXCOMM authority/rite/consequence audit, fill the required issuer parameter, replace removed crime helpers with a proven rite mapping in both prices and predicates, and migrate deprecated AI-only availability carefully.

These are separate features and may progress independently once their own gates close. The same missing native contract must not be repeated as a guessed implementation in either package.

## Package G Abdication and remaining alerts

Resolve SI-ABDICATE's current title/government/player succession contract and ensure “continue as heir” rather than unintended landless continuation. Finish SA-EDUCATION, SA-DEATH and SA-COURT UI/pre-death/recipient tests. Preserve inactive guest/death fallback paths unless a complete reference audit supports their cleanup.

## Package H Graphics and combined certification

Establish current rank frame mapping, then adapt both GFX distributions separately. Inspect all texture mismatch/consumer groups, keep local/public scope distinct and rebase the six post-effect assignments. Validate Gender Colour separately. Assets absent at a native same path are not deleted automatically.

Run [combined SP/MP playsets](test-protocol.md) only after the included packages pass individually. Update metadata per passing distribution; preserve identities and credits. No Workshop publication is included.

## Behavioral decisions that may become necessary

No current preference blocks this preparation. Only ask during implementation if concrete evidence forces a meaningful choice: strong-hook pardon semantics, engine refusal of post-start designer access, a native succession rule incompatible with heir continuation, or a graphical variant with competing intended coloring. Present the actual audited behavior, affected files and viable choices together. Do not ask merely because a mod is old or a native filename contains a DLC code.
